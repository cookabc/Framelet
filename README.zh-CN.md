# Framelet

一个原生 macOS 窗口与区域屏幕录制器。选择一个窗口或拖出一个区域，即可开始录制 ——
支持暂停、继续和重新录制，录制的片段可以预览并导出为视频或循环动画图。
当前版本只录制画面，所有处理都在本机完成。

## 环境要求

- macOS 15 或更高版本。
- 用于开发与测试的 Xcode 16 或更高版本中的 Swift 6 工具链。无第三方依赖。
- 构建和安装应用需要这台 Mac 上有效的 Apple Development 或 Developer ID 签名身份。
  仅编译和测试则不需要证书。

## 使用方法

从 `/Applications/Framelet.app` 启动应用。第一次录制时，请在系统询问时允许屏幕录制。

| 操作 | 方式 |
| --- | --- |
| 开始 / 停止 | `⌥⌘R`，或"New Recording"与"Stop"按钮 |
| 暂停 / 继续 | `⌥⌘P`，或浮动栏上对应的按钮 |
| 选择窗口或菜单面板 | 悬停高亮，然后点击、按 Return，或再次按录制快捷键 |
| 选择区域 | 拖出区域后松开 |
| 取消选择 | 按 Escape 或右键单击 |
| 移动录制区域 | 点击"Move area"，然后在区域内拖动；松开完成，右键单击取消。直接拖动把手也可以 |
| 在录制画面上绘制 | 浮动栏上的铅笔按钮，然后在区域上绘制 |
| 撤销标记 / 清除全部标记 | 绘制时出现的撤销与橡皮擦按钮 |
| 重新录制 | 浮动栏上的重新录制按钮会先保存当前视频，然后在同一区域上重新录制 |
| 导出 | 选择 MP4 或 GIF，设置起点与时长，然后保存 |
| 删除 | "Delete"，或在列表中右键单击一条录制，然后确认将其移到废纸篓 |

录制在倒计时后开始，默认三秒，可设为 5 秒或 10 秒。暂停的时间不计入视频长度。
关闭主窗口后应用会继续在菜单栏中运行。

这些快捷键注册为独占的全局热键，因此可能与其他应用冲突。注册会报告冲突而不是假定成功，
然后应用会回退到它还能占用的下一组组合 —— `⌃⌘R` 与 `⌃⌘P`，然后是 `⌃⇧⌘R` 与 `⌃⇧⌘P`。
实际正在使用的组合会显示在窗口、选择器和菜单栏中，当首选组合已被占用时，状态行也会说明这一点。

### 捕获点击后会关闭的内容

打开面板，按下录制快捷键（默认 `⌥⌘R`），然后把指针移到面板上使其高亮。
**再次按同一个快捷键即可在不点击的情况下确认。** 当选择器显示该提示时，Return 也可以确认。
让面板在倒计时期间保持打开，完成后用录制快捷键停止。

选择器永远不会成为 key window。Return 和 Escape 只在选择期间临时注册，选择器关闭时即释放；
已被其他应用占用的按键会从提示中省略。右键单击始终取消。键盘确认会立即关闭选择器；
鼠标确认仍会吸收第二次点击，以免把它传递给下层窗口。

菜单面板会被录制为固定的屏幕区域，包括之后出现在该区域中的任何内容。
有些应用会在外部点击或快捷键时自行关闭面板。对这类应用，请先拖出区域，再在倒计时期间重新打开面板，
倒计时可以提高到 5 秒或 10 秒。"Record Again"会复用同一区域。普通窗口仍使用窗口捕获，
拖动选择仍会选中任意区域。

## 录制、标注与文件

- 区域模式可以在任意显示器上选择，但一次录制仍限于单个显示器内。移动控件只会移动控件。
  点击"Move area"会激活一个虚线边框的移动面，在面内拖动，或直接拖动把手。松开即完成移动；
  右键单击可取消该模式。
- 区域模式请求最佳分辨率的合成显示器帧，并在编码前裁剪。只保存被选中的像素。
  选区会向内对齐到显示器像素网格和偶数输出尺寸，最多裁掉几个边缘像素，而不是对整个小区域重采样。
  处理整屏帧可能比直接捕获源矩形占用更多 GPU 内存。
- 窗口模式跟随所选窗口，并在录制开始时锁定输出尺寸。之后的尺寸变化由系统缩放处理；
  关闭目标窗口可能会中断捕获。
- 默认 30 fps，可选 60 fps。光标可显示或隐藏。可选的 ScreenCaptureKit 原生点击反馈默认关闭，
  且不需要全局键盘监听。
- 视频默认 H.264，或使用 HEVC，长边上限 3840 像素。屏幕内容的目标码率随编码像素和帧率缩放，
  小录制片段有 2 Mbps 的下限。这可能比系统默认压缩占用更多磁盘空间；它仍是有损的。
  HEVC 可以减小文件体积，但结果取决于内容和可用的编码器，并非固定的压缩比例。
- 暂停只是拦下帧而不重启捕获，并从媒体时间线中移除实际的暂停时段。
  暂停前与继续后的静态内容仍会计入有效录制时长。

### 在区域录制上绘制

使用铅笔按钮进入绘制模式。画笔、荧光笔、箭头、五种颜色、撤销和清除显示在展开后的控制栏内。
在绘制模式之外，绘制面会忽略鼠标输入，让目标保持可用。两个面板都不会成为 key window。

预览与编码后的视频使用同一个标注绘制器。已完成的标记会保持可见，标记变化时会刷新静态内容。
撤销和清除影响的是之后的帧，而不是已经保存的帧。标记使用桌面坐标，当录制区域移离它们时，
标记会从画面中消失。窗口模式刻意不提供固定区域的绘制或移动控件；
其控制栏会说明它跟随窗口，并且拖选区域后才能启用标注。

没有全局键盘监听或按键气泡。应用注册的控制快捷键不读取普通打字输入。点击反馈由
ScreenCaptureKit 自身提供。

### 预览、修剪与导出

- 视频为无声的 `.mp4`；动画图为循环的 `.gif`。
- 预览默认"Original size"：一个视频像素对应一个显示器像素，只有在片段放不下时才缩小。
  "Fit window"可以放大小片段，看起来会更柔和。这个开关只改变预览，不改变录制或导出的分辨率；
  放大一个小视频无法增加细节。
- 选择一种导出格式，设置起点与时长，然后保存为新文件。视频默认使用整个片段。
  完整的无声 MP4 导出会直接复制录制内容；较短的区间使用原生直通导出。
  直通会保留已编码的媒体，但不保证对每种编解码器都能做到任意帧精确的剪切。
- GIF 默认使用前 10 秒或整个较短片段，上限 60 秒。帧率和长边可配置。
  共享调色板取自采样的原始 RGB 值；GIF 的 256 色上限和直方图分箱仍可能改变颜色。
- 默认开启抖动以获得更平滑的渐变；关闭它可保持填充色平整。它并不是无损色彩开关。
  GIF 帧延时使用累积的厘秒边界，以避免时间漂移。
- 导出会先在目标位置旁暂存，成功后才替换目标。取消或失败会保留已有文件。
  覆盖原始文件或其硬链接 / 符号链接会被拒绝。

### 素材库与恢复

原始录制位于 `~/Library/Application Support/Framelet/Recordings/`。关闭窗口或导出从不会删除它们。
删除需要确认，并会把原始文件移到废纸篓；导出的副本保持不变。

当前录制会暂存在 `Unfinished` 会话目录中。只有完整且通过校验的视频才会进入最终素材库名称。
如果流中断但仍允许完成收尾，文件会带着中断提示保存，而不会被报告为正常成功。
非空的失败文件会保留以便检查，即使它们无法解码；恢复并不承诺修复被截断的 MP4。

启动时，Framelet 会尝试恢复当前的单文件录制和旧式分段录制。恢复失败会保留源文件。
只有已确认为空的目录或零字节的视频空壳会被丢弃；不可读的文件和未知的会话内容不会被静默删除。

帧率、光标可见性、点击反馈、编解码器、倒计时和 GIF 质量设置会在多次启动间保留，
主窗口的尺寸与位置也会保留。导出区间会为每个片段和每种所选格式重置。

完整的功能清单、移除项与范围决策见 [功能全集与取舍](docs/features.md)。

## 开发与安装

用 `git clone https://github.com/cookabc/Framelet.git` 克隆仓库，然后：

```sh
# 编译并测试，不安装应用
swift build
swift test

# 退出正在运行的应用，然后构建、签名并安装
bash scripts/build.sh
open /Applications/Framelet.app
```

`Package.swift` 可直接在 Xcode 中打开。构建脚本会生成图标，把可执行文件包装成
app bundle 并安装到 `/Applications/Framelet.app`。它首次选中的签名身份会存到
`.framelet-signing-identity` 中，之后的构建会复用。如果找不到可用的证书，它会直接失败，
而不是回退到 ad-hoc 签名。也可以通过 `FRAMELET_SIGN_IDENTITY` 环境变量显式指定身份。

本地签名配置、证书、环境文件、构建缓存和已安装的 bundle 都被 `.gitignore` 排除。
不要提交录制文件或个人的签名配置。把应用分发给他人还需要 Developer ID 签名与公证；
这个脚本只负责本地构建与安装。只想打包而不安装时，运行
`bash scripts/build.sh --package-only`；它会保持已保存的本地签名身份不变。

### 代码格式化

仓库使用 `.editorconfig` 和 `.swift-format` 保持一致格式，CI 会强制执行：

```sh
xcrun swift-format format --in-place --recursive Sources Tests scripts Package.swift
xcrun swift-format lint --strict --recursive Sources Tests scripts Package.swift
```

### 测试覆盖的内容

`swift test` 覆盖捕获几何、窗口选择、权限错误分类、媒体编码与解码、重复暂停与静态帧时长、
固定尺寸裁剪区域的移动、HEVC、标注位置与静态画面刷新、共享 GIF 调色板与抖动、帧延时、
非破坏性视频修剪、取消、源文件链接保护、恢复与删除边界。

交互测试直接驱动选择与标注输入，检查非激活面板与小屏幕控制布局，并注入一个捕获实现，以验证
首次录制的覆盖层接线、暂停 / 继续、被接受的移动、中断文件保留以及每个片段的导出区间。
最小主窗口尺寸会针对两种导出格式分别渲染。

GitHub Actions 在每次推送和拉取请求时运行测试、release 模式构建、格式检查，并检查构建脚本
和应用的信息文件。它不会安装应用、使用签名证书，也不会请求屏幕录制权限。

真实屏幕捕获、全屏空间、外接显示器和关闭被录制的窗口仍需要在已授权的机器上手动测试。
自动化测试不能替代这些检查。

作为可选的实时回归检查，请保持一个弹窗打开，并在有屏幕录制权限的 Mac 上运行
`FRAMELET_LIVE_PANEL_OWNER=magpie swift test --filter LivePanelCaptureTests`。
它会通过真实录制器驱动一次局部区域拖动，暂停、继续，并把视频保存到以 `LIVE_PANEL_CAPTURE`
打印出的临时目录中。请检查该视频以确认弹窗像素；测试只断言生命周期和文件创建。
测试进程激活可能会关闭瞬时面板，因此位于弹窗层级的持久测试窗口同样适用。普通测试套件会跳过
这项实时检查，并用合成帧另行验证裁剪方向、Retina 缩放、编码颜色、输出尺寸和静态帧时长。

## 目录结构

| 路径 | 内容 |
| --- | --- |
| `Sources/Framelet/Application/` | 应用入口、菜单栏和快捷键 |
| `Sources/Framelet/Capture/` | 选择面板、鼠标事件和屏幕捕获 |
| `Sources/Framelet/Recording/` | 录制状态、协调逻辑和浮动控制栏 |
| `Sources/Framelet/Library/` | 录制条目与文件命名 |
| `Sources/Framelet/UI/` | 主窗口、视频预览和按钮样式 |
| `Sources/FrameletCore/` | 捕获几何、计时、装配、导出和文件管理 |
| `Tests/FrameletCoreTests/` | 核心逻辑与媒体集成测试；`Support/` 负责合成视频 |
| `Tests/FrameletInteractionTests/` | 选择视图与录制素材库的回归测试 |
| `Resources/`、`scripts/` | 应用信息、图标生成和构建 / 安装脚本 |

## 权限排查

如果授权后录制仍然失败，请退出任何旧副本，从"应用程序"重新打开应用，并检查该副本的权限。
签名身份或位置发生变化后，权限可能不再生效。应用根据系统捕获请求的实际结果做判断，
从不自行修改或重置系统权限。

底层使用 Apple 的 [ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit)
和 [Image I/O](https://developer.apple.com/documentation/imageio)。
